# FinRisk_AI_Backend
Air-Gapped REST API skeleton for financial risk scoring (FastAPI, Pydantic, Docker Compose, MLflow)
Архитектурный прототип изолированного (Air-Gapped) REST API-сервиса для оценки финансовых рисков и скоринга транзакций. Проект спроектирован с учётом жёстких требований информационной безопасности банковского сектора и работы в закрытых контурах без доступа к внешней сети.

## 🏗 Архитектура и ключевые особенности

* **Асинхронный API-шлюз (FastAPI):** Реализованы промышленный эндпоинт мониторинга состояния сервиса (`GET /readyz`) и точка приёма транзакций для инференса моделей (`POST /api/v1/predict`).
* **Контрактная валидация данных (Pydantic):** Строгая типизация входящих финансовых транзакций (`user_id`, `amount`), включая контроль временного разрыва валютных операций (`currency_gap_days`) для выявления аномалий.
* **Air-Gapped сборка (Docker):** Настроен `Dockerfile` на базе `python:3.11-slim` с полной изоляцией установки пакетов от интернета (`--no-index --find-links`) из локального кэша кросс-платформенных Linux-колес (`manylinux` `.whl`).
* **Оркестрация и персистентность (Docker Compose):** Конфигурация запуска контейнера с пробросом сетевых портов и монтированием локальных томов (`volumes`) для надёжного сохранения логов экспериментов MLflow при перезапусках.

## 🛠 Технологический стек

* **Backend & Валидация:** Python 3.11, FastAPI, Uvicorn, Pydantic
* **Инфраструктура и MLOps:** Docker, Docker Compose, MLflow (инфраструктурная подготовка)
* **Зависимости под ML-контур:** Scikit-learn, LightGBM (конфигурация `requirements.txt` и оффлайн-пакетирование)

## 🚀 Инструкция по развёртыванию (Air-Gapped режим)

### 1. Предварительная подготовка оффлайн-пакетов (на машине с доступом в сеть)
Для сборки Linux-контейнера из среды Windows предварительно формируется локальная директория `./pip_packages` с бинарными `.whl` файлами под архитектуру `manylinux`:
```bash
pip download --platform manylinux_2_17_x86_64 --only-binary=:all: --no-deps -d ./pip_packages -r requirements.txt
```

### 2. Сборка и запуск в закрытом контуре
```bash
docker compose up --build -d
```

### 3. Проверка работоспособности
* **Healthcheck сервиса:** `GET http://localhost:8000/readyz` → ожидаемый ответ `{"status": "ready", "database_connection": "online"}`
* **Интерактивная документация Swagger UI:** `http://localhost:8000/docs`
